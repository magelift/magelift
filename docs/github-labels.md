# Suggested GitHub labels

These labels exist on the public repo. Use them so issues and PRs stay sortable.

| Label | Use |
| --- | --- |
| `good first issue` | ≤30-minute onboarding work (docs, tests, examples) |
| `help wanted` | Maintainer-approved external contribution |
| `provider/aws` | Certified AWS adapter |
| `provider/gcp` | Certified GCP adapter |
| `provider/ovh` | Experimental OVH adapter |
| `provider/scaleway` | Experimental Scaleway adapter |
| `area/cli` | Cobra commands |
| `area/docs` | MkDocs, ADRs, CONTRIBUTING, marketing |
| `area/config` | YAML schema and validation |
| `area/build` | Images, Composer package, BuildKit |
| `experimental` | Behavior that may break without a minor bump |
| `security` | SECURITY.md / advisory follow-ups |

Issue templates already set `bug` and `enhancement`. Add one area or provider
label with the type label. Open a `good first issue` when there is a real
≤30-minute docs, test, or example task. Do not keep placeholder issues open.
