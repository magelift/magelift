<objective>
Cover the catalog cells in combination rather than in isolation, at both levels where they can break.

Purpose: The AWS runtime wires web runtime, queue mode, the SigV4 OpenSearch sidecar, and Magento environment through one construction path, so cells interact unintentionally — that path is the project's own stated highest-risk file. Reading all 586 lines of the existing runtime tests surfaces six specific live code paths with no coverage, and the cell names themselves exist only one package up, so a single-level test cannot catch a mis-projection.

Output: A cheap projection matrix over all legal cells in the stack package, and a container-graph matrix in the runtime package covering exactly the six uncovered interactions plus the two already-covered anchors as sentinels.
</objective>

  <action>
Add one table-driven test over preset, search mode, queue mode, and web runtime that exercises only the pure projection helpers in this package — the queue consumer count, the effective queue mode, the Varnish image selection, and the search proxy image decision — and asserts the derived runtime argument shape. No Pulumi run, so all twenty-eight legal cells cost milliseconds and the matrix can be exhaustive where it is cheap.

Enumerate per preset rather than as a flat product. Three search modes times four queue modes times two web runtimes is twenty-four raw combinations, but several are illegal: provisioned search requires two or three subnets and cannot run under the preview preset, and the Amazon MQ queue mode is incompatible with preview by design because its multi-availability-zone cluster needs three zones while preview is two-zone. A flat enumeration either fails on those cells or, far worse, gets "fixed" by weakening the guard that makes them fail. Include the preview-with-Amazon-MQ cell explicitly as a case expected to be rejected, so the guard is under test rather than merely avoided.

Also cover the unset case per preset. Search mode and queue mode both have preset-derived defaults, and the default preview cell is one of the shapes an operator is most likely to run, so leaving defaults out would exclude the most common configuration from the matrix.

Follow the file's existing conventions: the table-and-subtest form used throughout the repo, standard-library assertions, fixtures inline. Reuse the existing spec construction helpers in this test file rather than adding a second fixture path.
