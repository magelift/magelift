<objective>
Add the two missing subnet-carve caps, then test all three boundaries on each.

Purpose: QUALITY-05 reads as a testing requirement, but only OVH has a cap to test. AWS carves three consecutive blocks per availability zone at four bits below the VPC prefix — sixteen slots total — with no index check, so six or more zones silently emits CIDRs outside the VPC. GCP carves two /24s per index with no index check, so a /20 parent silently overflows past index seven. There is nothing to assert until the guards exist, which makes this a code change the requirement does not name. The maintainer has scoped it in deliberately: add the caps, then boundary-test them.

Both defects are latent rather than live today — AWS presets bound zone counts to at most three, GCP zone lists likewise — but each is one user-supplied config field away from producing subnets outside the parent range, which is a network-isolation failure rather than a cosmetic one.

Output: Two small validations added at the existing reject-before-register points, and boundary tests at min, max, and max+1 for each.
</objective>

<task type="auto" tdd="true">
  <name>Task 1: Cap the AWS subnet carve and test its boundaries</name>
  <files>internal/cloud/aws/network/network.go, internal/cloud/aws/network/network_test.go</files>
  <behavior>
    - A zone count whose carve demand fits the sixteen available slots is accepted and produces exactly three times that many distinct CIDRs, all contained within the VPC prefix.
    - The largest zone count that still fits is accepted, and its highest carved block is still inside the VPC prefix.
    - One zone more than fits is rejected with an error naming the number of slots available and the number demanded.
    - Rejection happens before any Pulumi resource is registered, asserted the way the existing reject-before-register tests in this repo assert it.
    - The existing prefix validations — canonical IPv4 and no narrower than /24 — keep their current behaviour and messages.
  </behavior>
  <action>
Add an explicit capacity check in `validate` immediately before `subnetCIDRs` is called, comparing the carve demand against the number of blocks the chosen bit width actually provides. The carve widens the prefix by four bits, which yields sixteen blocks, and each zone consumes three of them for its public, private, and data tiers. Express the check in terms of the same arithmetic the carve uses rather than hard-coding sixteen, so the check and the carve cannot drift if the bit width is ever changed. Return an error naming both the available slot count and the demanded count, in the plain wrapped-error style this package already uses.

Do not restructure `subnetCIDRs` or change the CIDRs it produces for any currently valid input. This must be a pure addition of a rejection path: every configuration accepted today must still be accepted and must still produce byte-identical CIDRs, since a change there would silently move live subnets. The existing snapshot tests in this package are what prove that, so run the whole package rather than only the new test.

Add boundary tests in the existing test file mirroring the pattern the OVH network tests already use: plain functions, direct assertions on the carve helper and on `validate`, no Pulumi mocks needed for the pure arithmetic. Cover the minimum viable zone count, the maximum that fits, and one beyond. For the maximum case, assert that the last carved block is still contained by the VPC prefix — that is the assertion that would have caught the class of bug, rather than merely counting returned strings. For the rejection case, assert on the error message naming the limit, and separately assert through the Pulumi-mock path that no resources were registered.

Do not build a shared cross-provider carve helper. The four providers implement four genuinely different designs — AWS carves three blocks per zone at four bits down, OVH one /24 per zone, GCP two /24s per index with even and odd roles, Scaleway none at all — so a shared helper would need a strategy parameter and be harder to read than the small per-provider functions. It would also introduce cross-adapter coupling of the kind ADR 0002 and ADR 0008 exist to prevent, and it would not have caught the OVH bug it appears to target, because that bug was an off-by-one in a cap and the cap value is provider policy.

  <behavior>
    - Index zero produces a private and a public /24, both inside the parent prefix, with the private range preceding the public one.
    - The highest legal index for a given parent prefix produces two /24s still inside the parent prefix.
    - One index beyond the highest legal one is rejected with an error naming the limit, rather than silently returning ranges outside the parent.
    - The existing rejection of a parent prefix narrower than /20 keeps its current behaviour and message.
    - The caller rejects an over-long zone list before registering any Pulumi resource.
  </behavior>
  <action>
Add an index cap to the carve helper derived from the parent prefix, and reject at the caller before the subnet loop registers anything. The helper carves two /24s per index at an offset of twice the index, so the number of legal indices is half the number of /24s the parent holds — a /20 parent holds sixteen /24s and therefore eight legal indices, zero through seven. Express the cap from the prefix bits rather than hard-coding eight, so a future widening of the accepted prefix range stays consistent.

Reject at the caller as well as in the helper. The helper already returns an error, and the caller already propagates it, so the loop will stop — but a zone list that is too long should fail with a message about zone capacity rather than about a subnet index, which is what the operator can actually act on. Keep both messages; they answer different questions.

Create the package's first test file. It has no tests at all today, which is why a missing cap went unnoticed here while the equivalent OVH bug was caught and fixed. Mirror the OVH network test file's shape: plain top-level test functions, `t.Parallel()`, direct assertions on the unexported carve function, substring assertions on error messages. For the caller-level rejection, use the Pulumi-mock reject-before-register pattern the repo standardises on, asserting zero recorded resources.

Assert containment explicitly at the maximum index rather than only comparing strings. The failure this guard prevents is a subnet landing outside the parent range, so the test should check exactly that property.

Do not change the CIDRs produced for any currently legal index. As with AWS, this is a pure addition of a rejection path.
