    - `cost` with a positional argument is rejected by `cobra.NoArgs`.
    - `cost` without `--live` passes `Live: false` to the estimator; with `--live` it passes `Live: true`. The stub estimator records what it received.
    - `-o json`, `-o yaml`, and `-o table` each render the returned report; an unsupported `-o` value exits 2.
    - An estimator returning `platform.ErrNotSupported` exits 2 and the message names the target provider and runtime.
    - An estimator returning any other error exits 3 and the error carries a structured cause and next step through the `usererr` chain.
    - A target whose registered module exposes no cost estimator exits 2 with the same not-supported shape — reached by leaving `testCostEstimator` unset against the existing certified stub module, which implements no `CostEstimator`.
    - An unregistered target fails before the estimator is consulted, proving the planning gate runs first.
  </behavior>
  <action>
Use the harness the repo already has and no more: build options with the existing `testOptions` helper plus a `bytes.Buffer`, construct the command with `newCommandWithOptions`, write a `magelift.yaml` into `t.TempDir()`, and assert on the buffer contents and on `ExitCode(err)`. The `options` struct already carries a `testCostEstimator` seam that no test uses today, so a fake estimator satisfying `platform.CostEstimator` is the only new type needed. Zero Pulumi, zero credentials — that is what keeps this test runnable in a fully offline phase.

Do not modify `internal/cli/stub_module_test.go`. Plan 01-08 adds an experimental stub module and a tier field to `stubPlanned` there; touching the same file from this plan would collide. Assert the exit code is 2 and that the message identifies the target.

Follow the repo's test style exactly: standard-library `testing`, plain fatal comparisons, table-driven subtests for the flag and output-format variations, fixtures inline in the test file. No testify, no gomock.
